# 04. 薙刀式エミュレーションエンジン仕様(js/emulator.js)

最終更新: 2026-06-11

## 目的

実機なしで、通常のQWERTYキーボードの keydown/keyup から薙刀式の同時打鍵
(ファームウェアの「大岡式遅延確定」)を簡易再現してかなを生成する。
生成されたかなは `KanaMatcher` がお題のかな列と直接照合する(ローマ字を経由しない)。

## テーブルの自動構築

`KANA_KEYS`(02章)を逆引きして起動時に構築する。配列定義の単一情報源を保つため、
エンジン側に手書きの配列データは持たない。

| テーブル | 生成規則 | 例 |
|----------|----------|-----|
| `SINGLE[key]` | 1キー定義 | `SINGLE.f = 'か'`、`SINGLE.SP = ' '`(手動追加) |
| `LAYER[shift][base]` | 2キー定義で先頭がシフト能力キー | `LAYER.f.u = 'ざ'`、`LAYER.SP.v = '、'` |
| `COMBO2`(Map) | 2キー定義で先頭が非シフト。キーは sort 済み `'a,b'` | `'h,w' → 'きゃ'` |
| `COMBO3`(配列) | 3キー定義 | `[['j','w','h'], 'ぎゃ']` |
| `RELEVANT` | 上記すべてのキー集合 | u(シフト面専用)も含む ※過去バグ(07章) |

- シフト能力キー: `SP f j v m q`(定数 `SHIFT_KEYS`)
- `IGNORE_PAIRS = {f+g, j+h, v+m}` … 実機ではIME切替/Enter。かなを出さない(下記)。
- `CODE2KEY` … `KeyboardEvent.code` → キー名。物理位置基準なのでOSの配列設定に依存しない。
  t / y / u(単打が機能キー)のうち t・y はテーブルに現れないため自然に無視される。

## エンジンの状態とパラメータ

```
windowMs = 60   同時押し判定窓(実機40ms。UIで30〜120msに調整可、localStorage保存)
tapMs    = 200  シフトキー単独タップとみなす押下時間上限(実機 tap_ms=40ms)
down     Map<key, {t, used}>  押下中のキー(used=シフトとして消費済み)
pending  key[]                未確定キー(押下順)
```

実機より窓を緩めたのは練習導入のため(実機の40msは初心者には厳しい)。
`tapMs` の200msは「普通のタイプ速度のタップは単打、押しっぱなしはシフト」の経験値。

## イベント処理

- **keydown(key, t)**: 先に `flush(t)`(締切超過の保留分を確定=遅い連続打鍵の分離)、
  その後 pending に追加。
- **keyup(key, t)**: 先に `flush(t)`。キーが pending にある場合:
  - pending がそのシフトキー1つだけ → タップ判定(`!used && 押下時間 <= tapMs` なら単打かな)。
  - それ以外 → その場で `_resolve()`(キーを離した時点でチョード確定)。
  最後に pending / down から除去。
- **nextDeadline()**: `pending` が空、または「シフトキー1つだけ」なら null(=締切なし。
  シフトは相方を無期限に待てる)。それ以外は `最終keydown時刻 + windowMs`。
- ブラウザ側(app.js `scheduleFlush`)は keydown/keyup のたびに deadline へ setTimeout を張り直す。
  単打の表示遅延は最大 windowMs。

## チョード確定 `_resolve()` ― 優先順位

1. **combo3**: 保留中の非シフトキーをすべて含み、残りメンバが押下中キーで賄え、
   かつ最低1キーが pending にある組。
   例: j 押しっぱなし + w,h → ぎゃ。m,q,j 全シフトの ヴぁ もここで解決。
2. **combo2**: 保留中の非シフトキーがちょうど2つでペアが一致(w+h → きゃ)。
3. **全員シフト能力キーのチョード**(非シフトの保留なし):
   各キーを順にシフト候補とし、残り全部が `LAYER[シフト][残り]` で解決できる組を採用。
   **押し順不問**にするための探索(j+f でも f+j でも が)。解決不能なら何も出さない。
4. **レイヤ/単打**: 保留中の非シフトキーを押下順に、押下中シフト(押下時刻順)の
   レイヤを探して出力。`IGNORE_PAIRS` に該当したら無出力で消費。
   シフトがあっても対応かなが無ければ**単打にフォールバック**
   (例: f を押しながら k → い。実機の厳密動作とは異なるがロールオーバに寛容)。

確定したキーは pending から除去。シフトとして使われたキーは `used=true` になり、
後で離してもタップ(単打かな)を発火しない。押しっぱなしのシフトは pending に残り続け、
連続入力(Space押しっぱなしで さ→よ→…)を可能にする。

## 実機との意図的な差異

| 項目 | 実機 | 本エンジン | 理由 |
|------|------|-----------|------|
| 判定窓 | 40ms | 60ms 既定・可変 | 練習導入の容易さ |
| シフトタップ判定 | tap_ms=40ms | 200ms | 通常のタップ速度で単打が出るように |
| f+g / j+h / v+m | IME OFF/ON / Enter | 無出力 | かな練習に不要。ロールオーバ誤爆も実機同様「何も出ない」が正しいフィードバック |
| シフト+未定義キー | (おそらく無出力) | 単打にフォールバック | 高速打鍵のロールオーバ救済 |
| 編集モード | D+F / C+V | 非対応 | 文字入力でないため |

## KanaMatcher

エミュレーション用のかな直接照合。`units`(tokenize の結果)を連結した文字列に対し、
エンジンが emit したかなチャンク(1〜2文字)を `startsWith(chunk, pos)` で照合する。

- 単位境界をまたがない部分入力も自然に通る(しゃ を し→ゃ の2打で入れる等)。
- `idx`(現在単位)と `remaining()`(現在単位の残りかな)を提供し、
  かな表示の色分け・キーボードガイド・ヒント(`ゃ = Q+H 同時押し`)が追従する。
- 逆に「きや」に対して きゃ(combo)を打つと正しく miss になる。

## フォーカス喪失対策

window blur で keyup を取りこぼすと down/pending が残留するため、
blur 時に `engine.reset()` + flush タイマー解除(app.js)。
