# 03. ローマ字判定エンジン仕様(js/romaji.js)

最終更新: 2026-06-11

## 設計目標

実機(訓令式・ん=nn・促音=子音重ね・外来音=連結)の送出を**第一候補**として確実に通しつつ、
ヘボン式などの手打ち代替表記も受理する。判定は1打鍵ごとの前方一致。

## 処理の流れ

```
お題かな文字列
  → tokenize() ............ モーラ単位 unit[] に分割、各 unit に候補 alts[] とキー keys を付与
  → new Matcher(units) .... 1文字入力ごとに input(ch) で照合
```

## tokenize(text)

1. 文字を走査し、「次が SMALL_KANA(ぁ〜ゎ) かつ 現在が っ/ん 以外の変換可能かな」なら
   2文字を1単位に**結合**(きゃ、ふぁ、ヴぉ など)。
2. っ / ん は単独単位とし、候補は後段の `resolveContext` で文脈解決。
3. テーブルにない文字(漢字・カタカナ等)は**黙って捨てる**(カスタム/外部お題対策)。

### 単位の候補生成 unitAlts()

- 1文字 → `ROMAJI[c]` のコピー。
- 2文字(い段+ゃゅょ)→ `[実機表記(=子音+ya/yu/yo)] + HEPBURN_YOUON + クロス積`。
  例 しゃ → `['sya', 'sha', 'sixya', 'shixya', 'cixya', 'silya', ...]`
- 2文字(外来音等)→ `クロス積 + SPECIAL_UNITS`。
  例 ふぁ → `['huxa', 'fuxa', 'hula', 'fula', 'fa']`(先頭 huxa が実機表記)
- **クロス積**(`ROMAJI[c1] × ROMAJI[c2]`)を必ず含めるのがポイント。
  実機が拗音を分割送出する系統(し+小書きゃ=sixya)が来ても受理できる。

### resolveContext(units) ― っ/ん の文脈解決

- **っ**: 次単位の各候補の頭文字(子音)を1文字候補に。先頭は次単位の実機表記の頭文字
  (= 実機の促音表記)。母音・n・記号は除外。末尾の場合や次が母音なら `xtu/ltu/xtsu/ltsu` のみ。
- **ん**: 候補 `['nn', "n'"]`(先頭 nn = 実機表記)。次単位の実機表記が
  子音始まり(y, n を除く)の場合のみ `'n'` を追加(手打ちの n+子音 対応)。
- 解決は前から順なので、っ/ん が連続する場合は後者の候補が未解決のまま参照される
  → 保守的に nn のみになる(日本語としてほぼ出現しないので許容)。

## Matcher(状態機械)

状態: `idx`(現在単位)、`buf`(単位内の入力済み)、`committed[]`(確定済み単位の実入力)。

`input(ch)` の判定:

1. `buf+ch` がいずれかの候補の前方一致 → `buf` 更新。
   さらに候補と**完全一致**かつ**それより長い候補が無い**場合のみ単位確定(`unit`/`all`)。
   - 「長い候補があれば確定を遅延」が重要: ん の `n` と `nn` の共存を成立させる。
2. 前方一致しないが `buf` 自体が完全一致候補 →
   単位を確定して**同じ文字を次単位に持ち越して再帰**(ん に n 1つ + 次の子音、のケース)。
3. どちらでもない → `'miss'`(buf は保持。ユーザは正しい続きを打てばよい)。

`committed` は全文ヒント表示用(05章)。確定時の `buf` をそのまま記録するため、
ユーザが sha と打てば sha が、実機が sya を送れば sya が残る。

## 全文ローマ字ヒント(app.js updateHint)

```
typed = committed.join('') + buf                 … 緑表示
rest  = 現在単位の matchedAlt() の残り
        + 以降の単位の alts[0](=実機表記)の連結 … グレー表示
```

`matchedAlt()` は「buf に前方一致する最初の候補」。sha と打ちかけたら shi系に表示が追従する。

## 設計上の割り切り

- 候補は単位ローカルで閉じる。「直前の入力に応じて次単位の候補を絞る」ことはしない
  (例: っ を c で重ねた後の こ は ko/co どちらも受理される)。IMEとしては不正確だが
  練習用途では問題にならない。
- ローマ字モードでは Enter を完全無視(実機が 、。の後に IME確定 Enter を送るため)、
  スペースも無視(センターシフトの空振り対策)。どちらもミスに数えない。
